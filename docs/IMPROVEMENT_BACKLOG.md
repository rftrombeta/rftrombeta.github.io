# Backlog de melhorias

## Critérios

Este backlog separa defeitos observáveis, riscos inferidos e evoluções opcionais. Prioridade é uma recomendação baseada no impacto potencial para recrutadores/usuários e não em medições de produção. Itens do backlog não constituem autorização para implementação.

Estados: `OPEN` = oportunidade registrada, ainda sem implementação; `NEEDS_VALIDATION` = hipótese que exige verificação antes de classificar como defeito definitivo; `IMPLEMENTED_PENDING_VALIDATION` = alteração de código realizada, mas critérios de aceite ainda precisam de validação; `FUNCTIONALLY_HOMOLOGATED` = critérios funcionais aprovados na validação manual informada, sem implicar conformidade WCAG; `OWNER_APPROVED` = conteúdo editorial aprovado pelo proprietário, sem comprovar externamente as alegações. `PENDING_OWNER_INPUT` indica dependência de evidência ou confirmação do proprietário. Critérios de aceite descrevem resultado desejável, não trabalho autorizado.

## Ordem sugerida

Os itens já marcados `FUNCTIONALLY_HOMOLOGATED` e `OWNER_APPROVED` permanecem no backlog como histórico. As próximas oportunidades ainda abertas são:

1. Definir validação automatizada mínima quando autorizada (TEST-01).
2. Tratar metadados e dependências após confirmar URLs e medir o comportamento (SEO-01 e PERF-01).
3. Avaliar estrutura de conteúdo sem criar abstração desnecessária (CONTENT-01).
4. Melhorar evidências profissionais somente com insumos aprovados pelo proprietário (PROF-01).
5. Fazer revisão editorial pendente após confirmação do proprietário (EDIT-01).
